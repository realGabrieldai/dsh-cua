# dsh-cua — FROZEN INTERFACE CONTRACT (v1)

Any component that disagrees with this file is wrong. Do not edit this file without telling the Lead;
it is the shared interface between the Swift core, the MCP server, the docs and the verifier.

## 0. What this is

`dsh-cua` gives DSH (and any MCP client) a **macOS computer-use layer** with the same tool surface as
OpenAI Codex's built-in CUA (`list_apps`, `get_app_state`, `click`, `type_text`, `press_key`, `scroll`,
`drag`), implemented natively instead of by driving a visible browser window.

**The hard product requirement: it must never steal the user's screen.** Specifically:

1. It never calls `NSRunningApplication.activate(...)`, never `open -a`, never brings a window forward.
2. Screenshots are **window-scoped** (ScreenCaptureKit `SCScreenshotManager`, one window), never a
   full-display grab, and never trigger any UI change.
3. Input is delivered with `CGEventPostToPid` (targeted at the app's PID) or via the Accessibility API,
   so the physical cursor does not move and the frontmost application does not change.
4. Every command reports `frontmostApp` before/after and the process **exits non-zero** if the
   frontmost app changed as a result of the call. A focus steal is a bug, not a warning.

## 1. Binary

One Swift executable, product name `dsh-cua`. SwiftPM package `dsh-cua`, platform `.macOS(.v14)`.

```
dsh-cua <command> [options]
```

Global options accepted by every command: `--json` (machine output, single JSON object on stdout),
`--quiet`, `--timeout-ms <n>` (default 15000), `--help`.

### 1.1 `doctor`
Reports environment + permissions. Never fails hard on missing permissions (exit 0), so it can be used
as a preflight.
```json
{"ok":true,"macos":"27.2","binary":"/abs/path","permissions":{"accessibility":true,"screenRecording":false},
 "permissionHints":{"accessibility":"System Settings → Privacy & Security → Accessibility",
                    "screenRecording":"System Settings → Privacy & Security → Screen & System Audio Recording"},
 "screenRecordingApi":"SCScreenshotManager","frontmostApp":{"bundleId":"com.apple.Safari","pid":501}}
```

### 1.2 `list-apps`
```json
{"ok":true,"apps":[{"name":"Safari","bundleId":"com.apple.Safari","pid":501,"active":true,
                    "hidden":false,"windowCount":2}]}
```
`active` = frontmost. Ordering: frontmost first, then alphabetical by name. `--all` includes
background/UI-less agents (default: apps with a bundle id and at least one window, or `.regular`
activation policy).

### 1.3 `list-windows [--app <target>]`
```json
{"ok":true,"windows":[{"id":4211,"pid":501,"app":"Safari","title":"Apple",
                       "bounds":{"x":0,"y":0,"w":1440,"h":900},
                       "layer":0,"onScreen":true,"focused":true}]}
```
`id` is the CGWindowID. `focused` = the app's focused/main window (AX), not "is frontmost".
With `--app`, only that app's windows.

### 1.4 `get-app-state --app <target> [--screenshot <path>] [--max-depth N] [--max-nodes N]`
`<target>` is one of: bundle id (`com.apple.Safari`), pid (`pid:501`), or app name (`Safari`).

```json
{"ok":true,
 "app":{"name":"Safari","bundleId":"com.apple.Safari","pid":501},
 "frontmostApp":{"bundleId":"com.apple.Safari","pid":501,"unchanged":true},
 "windows":[{"id":4211,"title":"Apple","focused":true,"bounds":{"x":0,"y":0,"w":1440,"h":900}}],
 "tree":[{"ref":"e1","role":"AXWindow","subrole":"AXStandardWindow","title":"Apple",
          "value":null,"enabled":true,"focused":true,
          "frame":{"x":0,"y":0,"w":1440,"h":900},
          "actions":["AXRaise"],"children":[ /* ... */ ]}],
 "stats":{"nodes":312,"truncated":false,"maxDepth":12},
 "screenshot":{"path":"/tmp/dsh-cua-501-4211.png","width":1440,"height":900,"windowId":4211,"scale":2}}
```
Rules:
- Defaults: `--max-depth 12`, `--max-nodes 1500`; truncation sets `stats.truncated = true` (never silently).
- `--screenshot` omitted ⇒ no capture at all (fast path, no Screen Recording permission needed).
- Screenshot captures **only** `windows[0].id` (the app's focused window) unless `--window <id>` is given.
- `ref` values (`e1`, `e2`, …) are valid until the next `get-app-state` for the same pid. They are
  persisted to `$XDG_CACHE_HOME|~/.cache/dsh-cua/snapshot-<pid>.json`.
- Nodes with no title/value/role of interest are still emitted; the MCP layer prunes.

### 1.5 `click --app <target> (--element <ref> | --x <n> --y <n>) [--button left|right|middle] [--count 1]`
Coordinates are **global display points** (top-left origin, same space as CGEvent). Resolution order:
1. `--element <ref>` → look up the cached snapshot, verify pid still alive, re-read the element's frame,
   then perform its `AXPress` action if available.
2. `--x --y` → `AXUIElementCopyElementAtPosition` at that point; if it yields an element of the target
   app with `AXPress`, press it.
3. Fallback → `CGEventPostToPid` mouse down/up at that point.
```json
{"ok":true,"target":{"ref":"e7","role":"AXButton","title":"Sign in"},
 "method":"ax-press","frontmostApp":{"bundleId":"com.apple.Safari","pid":501,"unchanged":true}}
```
`method` ∈ `ax-press` | `ax-set-value` | `cg-event`.

### 1.6 `type-text --app <target> --text <string> [--element <ref>] [--submit]`
With `--element` and a settable `AXValue`, sets the value directly (`method":"ax-set-value"`) — this is
the no-focus path. Otherwise posts unicode keyboard events to the pid (`method":"cg-event"`).
`--submit` posts Return afterwards. Same JSON envelope as `click`, plus `"chars": <n>`.

### 1.7 `press-key --app <target> --key <keyname> [--modifiers cmd,shift,opt,ctrl]`
Key names: `return enter tab space escape delete backspace up down left right home end pageup pagedown
f1..f20` and single characters. JSON envelope as `click`, plus `"key":"..."`, `"modifiers":[...]`.

### 1.8 `scroll --app <target> --dx <n> --dy <n> [--x <n> --y <n>]`
Posts scroll wheel events to the pid. Positive `dy` scrolls down (content up). JSON as `click`.

### 1.9 `drag --app <target> --from <x,y> --to <x,y> [--button left]`
Posts mouse-down, interpolated drags (≥10 steps), mouse-up to the pid. JSON as `click`.

## 2. JSON envelope (every command, `--json`)

Success: `{"ok":true, ...command fields...}`
Failure: `{"ok":false,"error":{"code":"<CODE>","message":"<human>","detail":{...}}}`
Exit codes: `0` ok · `2` bad usage · `3` app/window not found · `4` permission denied ·
`5` stale ref · `6` timeout · `7` focus changed (hard failure) · `1` other.

Error codes: `BAD_USAGE`, `APP_NOT_FOUND`, `WINDOW_NOT_FOUND`, `PERMISSION_DENIED`,
`STALE_REF`, `TIMEOUT`, `FOCUS_CHANGED`, `UNSUPPORTED`, `INTERNAL`.

## 3. Safety

- Never target a terminal or password field. Hard-blocked bundle ids (mirroring Codex's CUA):
  `com.apple.Terminal`, `com.googlecode.iterm2`, `dev.warp.Warp-Stable`, `com.github.wez.wezterm`,
  `net.kovidgoyal.kitty`, `co.zeit.hyper`, `com.apple.SecurityAgent`,
  `com.apple.systempreferences` password sheets. Blocked ⇒ `UNSUPPORTED` with a clear message.
  `DSH_CUA_ALLOW_BLOCKED=1` overrides (documented as dangerous).
- `DSH_CUA_DRY_RUN=1` prints the resolved plan and performs no input.
- Refuse to type into an AX element whose `AXRole` is `AXSecureTextField` or whose subrole indicates a
  secure field ⇒ `UNSUPPORTED`.

## 4. MCP server

`mcp/server.mjs` — Node ≥ 18, **stdlib only**, newline-delimited JSON-RPC 2.0 over stdio
(MCP `2024-11-05`-style: `initialize`, `tools/list`, `tools/call`, `notifications/initialized`).
It shells out to the `dsh-cua` binary (`DSH_CUA_BIN` overrides the path).

Tool names are exactly the Codex CUA names, snake_case:
`list_apps`, `get_app_state`, `click`, `type_text`, `press_key`, `scroll`, `drag`, `list_windows`,
`doctor`.

`get_app_state` returns MCP `content` of type `text` with a compact JSON payload, and, when
`--screenshot` was requested, an `image` content block (`{type:"image", data:<base64>, mimeType:"image/png"}`)
so the model sees the pixels. Tool results set `isError: true` when the CLI envelope has `ok:false`.

### 5.1 Deviation from the original plan (2026-10-22)

There is **no XCTest target**. This machine has only the Command Line Tools, which ship
neither `XCTest` nor `swift-testing`, so `swift test` cannot compile here. The assertions
therefore live in `Sources/DshCuaCore/SelfTest.swift` and run as `dsh-cua selftest`
(exit 0/1, `--json` supported). CI runs `swift build -c release` + `dsh-cua selftest`
instead of `swift test`. Everything else in this contract is implemented as written.

`DshCuaCore` is a library and `dsh-cua` is a thin `main.swift` so the assertion suite can
be imported and executed by the binary itself.

## 6. Non-goals (v1)

Windows/Linux; OCR; video; driving the *user's* frontmost app on purpose; CAPTCHA solving;
bypassing TCC. If Screen Recording is not granted, `get-app-state` still works without a screenshot.
